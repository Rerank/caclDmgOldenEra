# План реализации — калькулятор входящего урона (HoMM: Olden Era)

Источник вёрстки: `temp/html/index.html` (эталон только для чтения; `design.png` — устаревшая версия).
Источник механики: https://paradrew.com/ru/olden-era/guides/pvp-combat-mechanics/

---

## Принятые решения

### Формула

```
урон = кол-во × урон × (20 + ATK) / (20 + DEF) × M
M   = max(0.10, 1 + исх% − вх%)          // проценты складываются, пол 10%
```

- `ATK` / `DEF` — уже с атакой и защитой героя.
- Базовый множитель `(20+ATK)/(20+DEF)` максимума не имеет, минимум 0.
- Штраф за дистанцию задаётся прямо в процентах, 0…50%. Отдельный множитель. Из расстояния он не считается: у части существ выстрел штрафа не имеет вовсе.
- Округление **к ближайшему**, один раз, в самом конце. Затем финальный минимум — 1. В гайде правила нет, выведено сверкой с игрой: 23.2 → 23, 41.76 → 42.
- Удачу не считаем и не закладываем (рандом не место в калькуляторе).

### Ответный удар

- Наносят **выжившие** после первого удара.
- Колонки перекрёстные: `макс` входящего = выжившие после **мин** удара × их **макс** урон; `мин` — наоборот; `сред` — от средних.
- Отсутствует, если включена дистанционная атака или все существа защищающегося погибли. Карточка тогда не рендерится.

### Поля

| Параметр | По умолч. (атак. / защ.) | min | max | шаг |
|---|---|---|---|---|
| Герой: атака | 0 / 0 | 0 | 99 | 1 |
| Герой: защита | 0 / 0 | 0 | 99 | 1 |
| Здоровье max | 35 / 25 | 1 | 9999 | 1 |
| Здоровье текущее | = max | 1 | = max | — |
| Кол-во | 10 / 8 | 1 | 9999 | 1 |
| Атака | 10 / 8 | 0 | 99 | 1 |
| Защита | 12 / 8 | 0 | 99 | 1 |
| Урон min / max | 7–9 / 3–6 | 0 | 9999 | — |
| Штраф | 0 | 0 | 50 | 10 |
| Увел. исх. урона | 0 | 0 | 500 | 5 |
| Умен. вх. урона | 0 | 0 | 100 | 5 |

Здоровье и урон задаются парой полей без кнопок ±: такие значения переписывают
целиком. Атака и защита показываются вместе с бонусом героя, границы полей
сдвинуты на этот бонус. Текущее здоровье — это здоровье верхнего, ещё не
добитого существа: входящий урон сначала добивает его.

### Результаты

- Слепок = параметры существа из панели на момент удара. Расшифровка = формула этого урона.
- Слепок и таблица в карточке — про сторону, которая **получает** урон: карточка стоит под её панелью. Расшифровка — про ту, которая бьёт.
- Нулевые параметры ни в слепке, ни в расшифровке не показываются.
- Свежий результат сверху; «Закрепить» уводит его вниз, в стопку закреплённых. Любая правка параметров убирает незакреплённый результат.
- Появление и уход панели анимируются; закрепление и открепление — нет, там ничего не появляется и не исчезает.

### Техника

- Состояние — `useState` внутри хука `useCalculator()`. Reducer не нужен (вернёмся, если появится undo или пересчёт закреплённых).
- Стили — глобальный BEM, один CSS-файл на компонент, импорт из `.tsx`. Без CSS Modules.
- Картинки — `src/assets/images`, импортом (Vite сам проставит `base` и хеш).
- Тесты — `vitest`, ~8 краевых кейсов на `damage.ts`.
- Репозиторий: `https://github.com/Rerank/caclDmgOldenEra` → `base: '/caclDmgOldenEra/'`.
- Коммиты и пуши делает только владелец репозитория.

## Этапы

> Ниже — журнал того, как проект собирался. Этапы 1–6 пройдены; описания
> оставлены как есть, поэтому в мелочах они расходятся с текущим кодом.
> Что верно на сегодня — в разделе «Принятые решения» выше.

### Этап 1. Каркас

Убрать из шаблона `src/App.css`, `src/index.css`, `src/assets/react.svg`, `public/vite.svg`.

1. `src/styles/variables.css`, `src/styles/base.css` — копия из `temp/html/css`, без правок.
2. `src/assets/images/` ← 6 файлов из `temp/html/images`.
3. `index.html` — `lang="ru"`, заголовок, preconnect + Google Fonts, `<body class="page">`.
4. `vite.config.ts` — `base: '/caclDmgOldenEra/'`.
5. `main.tsx` — импорт двух глобальных CSS.
6. `i18n/ru.ts` — заводим сразу, строки складываем туда с первого компонента.
7. `components/AppHeader.tsx` + `app-header.css`.

**Готово, когда:** `npm run dev` показывает фон `#e8e1d3`, шапку в Spectral, формулу в JetBrains Mono, двойную линию под заголовком.

### Этап 2. UI-кит и статическая копия вёрстки

Состояния ещё нет — везде константы и пустые обработчики.

1. `components/ui/`: `Button`, `IconButton`, `ParamRow`, `Toggle`, `Disclosure`, `Stepper`, `NumberField` + их CSS.
   `Stepper` сразу делаем «правильным»: наружу `value: number` / `onChange`, внутри — черновая строка, чтобы поле можно было очистить и набрать заново; нормализация и зажим в границы на `blur`.
2. `components/`: `HeroPanel`, `TemplateField` (нативный `<select>` с одной опцией «Свой»), `RangedFields`, `UnitSide`.
3. `components/`: `ResultTable`, `ResultCard`, `ResultPanel`, `Results`.
4. `App.tsx` — раскладка `battle` (grid-areas), две стороны, кнопка обмена, блок удара, стопка результатов.

**Готово, когда:** страница совпадает с `temp/html/index.html` на 1280 / 900 / 600 / 360 px.

### Этап 3. Состояние и ввод

1. `domain/types.ts` — `Side`, `Input`, `Outcome`, `Strike`, `Result`, `Entry`.
2. `domain/rules.ts` — `RULES`, `F` (границы полей), `DEFAULT_INPUT`.
3. `state/calculator.ts` — `useCalculator()`: `input`, `fresh`, `pinned` + `patch`, `patchAttack`, `swap`, `strike`, `pin`, `unpin`.
4. Прокинуть `value` / `onChange` во все поля.
5. Правила ввода: зажим по границам на `blur`, `damageMin ≤ damageMax` (подтягиваем второе поле, ввод не блокируем), пустая строка допустима во время набора.
6. «Гексы» рендерятся только при включённом тумблере.
7. Подсветка: в полях «Атака» и «Защита» число окрашивается в цвет стороны, когда у героя есть соответствующий бонус. В поле остаётся **своё** значение существа (иначе его нельзя редактировать); итоговое с героем видно в расшифровке, плюс `title` вида «10 + 4 героя = 14».
8. Маркер у «Дополнительно», когда исх. или вх. ≠ 0.

**Готово, когда:** все поля управляются, границы держатся, гексы прячутся, подсветка и маркер работают. «Удар» пока ничего не делает.

### Этап 4. Расчёт

1. `domain/damage.ts` — `calculate(input): Result`. Чистые функции, ноль React и ноль строк интерфейса.
2. `domain/damage.test.ts` — 8 кейсов с посчитанными вручную ожиданиями:
   - перекрёстность веток ответного удара (макс входящего — от мин удара);
   - пол 10% при «умен. вх. 100%»;
   - финальный минимум 1 при огромной защите;
   - кап штрафа за дистанцию (гексы 8 и гексы 20 дают один результат);
   - округление вниз ровно один раз;
   - точное деление урона на HP: 75 / 25 → 3 убитых, верхний на полном здоровье;
   - `counter === null` при `ranged`;
   - `counter === null`, когда все погибли.
3. `components/breakdown.ts` — строка расшифровки из `Strike` + `Input`, слова из `i18n`.
4. «Удар» считает и кладёт результат в `fresh`.
5. Правка CSS: модификатор `result-panel__body--single` (одна колонка), когда ответного удара нет.

**Готово, когда:** тесты зелёные и один расчёт сверен вручную в браузере.

### Этап 5. Стопка результатов

1. «Закрепить» переносит свежий результат в стопку; новые закреплённые — выше старых.
2. «Открепить» удаляет из стопки.
3. Слепок у закреплённых: `Свой · HP 35 · атака 14 · защ. 15 · урон 7–9 · 10 шт · исх. +25% · вх. −0%`; при дистанционной атаке добавляется `· 5 гексов (−20%)`.

**Готово, когда:** закреплённые панели не исчезают при новых ударах и читаются в отрыве от формы.

### Этап 6. Обмен сторонами и края

1. Обмен сторонами: меняются местами обе стороны целиком (существо + герой + проценты); `ranged` и `hexes` остаются на месте — это свойства удара.
2. «Удар» дизейблится, пока есть поле в незаполненном состоянии.
3. Края: все погибли; ответного удара нет; `damageMin = damageMax`; нулевые атака и защита; максимальные значения.

**Готово, когда:** ни один край не даёт `NaN`, пустую таблицу или сломанную вёрстку.

### Этап 7. Сборка и GitHub Pages

1. Проверить `npm run build && npm run preview` с учётом `base`.
2. `.github/workflows/deploy.yml` — Actions: `build` → `upload-pages-artifact` → `deploy-pages`. Без дополнительных зависимостей.
3. Прогнать `npm run lint`.
4. Коммит и пуш — делает владелец репозитория.

**Готово, когда:** страница открывается по адресу Pages, картинки и шрифты на месте.

## Отложено

- Комбобокс с поиском и справочник существ — когда будут данные.
- Стрелок в упор: сам штраф вводится вручную, но ответный удар в этом случае игра всё-таки даёт, а калькулятор при включённой дистанционной атаке его не считает.
- Английская локализация: словарь уже отдельным файлом, переключателя нет.
- Раздельные слои «общего» и «типового» урона.
- Удача.
